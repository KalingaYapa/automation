# Repository instructions

When adding an automation test case, update `docs/test-case-catalog.md` in the same change. Include its test case ID, name, automation method, objective and expected result. Keep the catalog aligned when a case is renamed, changed, disabled or removed. Distinguish sample-template cases from application cases when IDs overlap.

When writing new automation tests, follow `docs/test-writing-guide.md` for the team test/Page Object structure, step logging, frame handling and code-quality checks. For every future test-writing request, use the PDF-derived naming and grouping standard recorded in that guide: lowercase module packages, numbered module test/page class pairs, globally unique verify methods, and exactly the module and P<n>-module groups. Do not copy legacy class-name/High groups, add per-test retryAnalyzer/priority or commit enabled=false. Reuse existing framework/setup APIs without duplicating login. Handle legacy imports and suite/report references as described in the guide; documentation updates alone do not migrate existing code.
