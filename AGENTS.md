# Repository instructions

When adding an automation test case, update `docs/test-case-catalog.md` in the same change. Include its test case ID, name, automation method, objective and expected result. Keep the catalog aligned when a case is renamed, changed, disabled or removed. Distinguish sample-template cases from application cases when IDs overlap.

When writing new automation tests, follow `docs/test-writing-guide.md` for the team test/Page Object structure, step logging, frame handling and code-quality checks. For every future test-writing request, use the PDF-derived naming and grouping standard recorded in that guide: lowercase module packages, numbered module test/page class pairs, globally unique verify methods, and exactly the module and P<n>-module groups. Do not copy legacy class-name/High groups, add per-test retryAnalyzer/priority or commit enabled=false. Reuse existing framework/setup APIs without duplicating login. The standard layout is implemented: reuse a_testbase.BaseClass, d_loginpage.BasePage and HomePage, with ReusableMethods navigation. Update suite/report references together when changing classes or groups. Run scripts/check_framework_standards.py, compile and execute the relevant suites. Keep archived docs/templates examples outside application execution.

Logging is required in implementation, not just documentation: use a class-specific private static final Log4j2 logger, INFO start/observed-result/successful-finish messages, DEBUG before/after actions, assertions, frame changes and cleanup, and central ERROR failure logging. Capture an observed value once and reuse it; never log credentials or issue extra WebDriver reads from log arguments. Keep module DEBUG loggers enabled and verify both terminal and file output. A successful finish must occur only after assertions and required cleanup succeed.

The user's supplied sample is the required implementation format: explicit enabled=true and module/priority groups; test start log, shared login/search/Edit call inside each test method, explicit page construction and logged WebDriver frame/default-content steps. Do not hide navigation in subclass BeforeMethod or whole scenarios in private test helpers. Fixed PageFactory fields use FindBy(xpath=...), dynamic section-scoped lookups use By.xpath, and Page actions use BasePage.elementClick. Page methods do not switch frames. Keep the current functional behaviours and Undo cleanup; do not add Accept Change/Code View merely because they appear in the example. Paragraph tests belong to para.Para1TestCase/ParaPageObjects1 and Para/P2-Para.
